## 💡 Почему этот скилл необходим: Архитектура Evidence-Driven

Современный AI-поиск объединяет **традиционный поиск (Retrieval)** и **генеративный синтез (Generation)**:
1. **Двухэтапный конвейер:** Традиционное SEO (краулинг, техническая индексация, PageRank) определяет, попадет ли страница в пул кандидатов выдачи (например, top-5 результатов Google). Когда кандидаты извлечены, **в дело вступает GEO**: нейросеть цитирует факты из источников с наивысшей доказательной плотностью и структурной ясностью.
2. **Эффект демократизации:** В исследовании Принстона (KDD 2024, Table 2) оценивалась выдача top-5 результатов Google: сайты с 5-й позиции при оптимизации методом *Cite Sources* получили **+115.1% к доле цитирования в ответах AI** (в то время как сайты с 1-й позиции просели на **-30.3%**), доказав, что доказательная плотность позволяет превзойти лидеров внутри пула кандидатов.
3. **Позиция ответа критична (Метрика PAWC):**  
   $$\text{PAWC}(c, q) = \sum_{s \in S_c} \frac{|s|}{L_r} \cdot e^{-\alpha \cdot \frac{\text{pos}(s)}{N_r}}$$
   Поскольку вес цитирования предложений экспоненциально затухает ($\sim 2.7\times$ при базовом $\alpha = 1.0$) по мере удаления предложения в *сгенерированном ответе LLM*, вынос прямого ответа в лид-абзац исходного текста выступает практической RAG-эвристикой: это максимизирует вероятность того, что извлеченный пассаж содержит законченное утверждение и попадет в открывающие предложения ($\text{pos}(s)=0$) ответа нейросети.

```
                 ЦЕЛЬ АУДИТА
                     │
                     ▼
               ┌───────────┐
               │ DISCOVERY │ (URL, HTML, Codebase)
               └─────┬─────┘
                     ↓
          ┌─────────────────────┐
          │ OBSERVABLE SIGNALS  │ (DOM-селекторы, HTTP-заголовки, robots, schema)
          └──────────┬──────────┘
                     ↓
          ┌─────────────────────┐
          │ EVIDENCE LEDGER     │ (Finding ID, Selector, Raw Value, PASS/FAIL/UNKNOWN, Tier)
          └──────────┬──────────┘
                     ↓
          ┌─────────────────────┐
          │ 6-TIER RULE ENGINE  │ (От Tier A Стандартов до Tier F Гипотез)
          └──────────┬──────────┘
                     ↓
          ┌─────────────────────┐
          │ CONFIDENCE ENGINE   │ (Наблюдаемый Score vs Полнота аудита Coverage %)
          └──────────┬──────────┘
                     ↓
               ИТОГОВЫЙ ОТЧЕТ
```

> **Протокол Evidence Ledger и Инвариант «Неизвестно ≠ Плохо»:**
> 1. **Протокол Evidence Ledger:** Аудит не выносит субъективных суждений без фактов. Каждая находка обязана содержать точный селектор DOM или HTTP-заголовок, наблюдаемое значение и эпистемический уровень (`Tier A` – `Tier F`).
> 2. **Неизвестно ≠ Плохо:** Если полевые данные (CrUX, логи сервера, сторонний ссылочный индекс) недоступны, статус фиксируется как `UNKNOWN` и **не штрафует** итоговый балл. В отчете явно разделяются:
>    - **Observable Technical Score (0–100):** Оценка строго по наблюдаемым сигналам (High Confidence).
>    - **Observation Coverage (%):** Процент фактически проверенных критериев от общего числа.
>    - **GEO Readiness Index (0–100):** Качественная эвристическая модель готовности к цитированию (Medium Confidence).

## ⚡ 5 Режимов Работы

| Режим | Триггерные фразы | Что делает |
|---|---|---|
| **1. `audit`** | `аудит сайта`, `проверь SEO`, `посчитай GEO score`, `почему упал трафик` | Таблица Evidence Ledger, Observable Technical Score (0–100, High Confidence), процент покрытия Observation Coverage % и GEO Readiness Index (0–100, Medium Confidence) с планом правок P0 / P1 / P2. |
| **2. `optimize`** | `перепиши под AI`, `сделай чтобы ChatGPT цитировал`, `front-load`, `улучши PAWC` | Превращает водянистые рекламные тексты в плотные блоки по формулам Принстона KDD 2024. |
| **3. `schema`** | `сгенерируй JSON-LD`, `добавь микроразметку`, `rich snippets`, `FAQ schema`, `HowTo` | Создает валидный объединенный `@graph` JSON-LD блок в `<head>`, связывающий Organization, WebSite, WebPage, Service, FAQ (для RAG-извлечения ответов LLM; Примечание: Google Search полностью прекратил показ FAQ rich results для всех сайтов с 7 мая 2026 года) и HowTo. |
| **4. `ai-files`** | `настрой llms.txt`, `исправь robots.txt для AI`, `открой доступ GPTBot` | Формирует безопасный `robots.txt` с контролем индексации приватных путей + файл-манифест `llms.txt` (комьюнити-пропозал). |
| **5. `strategy`** | `контент-план под AI`, `карта тематического авторитета`, `семантическое ядро` | Проектирует кластеры статей и лендингов, ориентированных на длинные диалоговые запросы в Perplexity и ChatGPT. |

*(Примечание: Помимо 5 пользовательских режимов выше, скилл включает внутренний тестовый харнесс safety_check для строгой защиты от галлюцинаций).*

## 🛡️ Управление краулингом: Безопасный шаблон `robots.txt` без нежелательной индексации

Согласно стандарту **RFC 9309**, блок директив для специфичного краулера полностью переопределяет общий блок `*`. Если открыть боту доступ через `Allow: /`, но не продублировать запреты, он сможет проиндексировать `/api/`, `/admin/`, `/checkout/` и `/auth/`. *(Примечание: Согласно RFC 9309 §1, robots.txt управляет поведением поисковых роботов, но НЕ является механизмом авторизации или безопасности; реальная защита требует HTTP 401/403, WAF и сетевых списков доступа).* `ultimate-seo-geo` применяет корректный шаблон:

```txt
# Стандартные поисковые роботы
User-agent: *
Allow: /
Disallow: /api/
Disallow: /admin/
Disallow: /private/
Disallow: /checkout/
Disallow: /auth/

# Явные разрешения для AI-краулеров (с дублированием закрытых путей по RFC 9309)
User-agent: GPTBot
User-agent: ChatGPT-User
User-agent: OAI-SearchBot
User-agent: ClaudeBot
User-agent: Claude-SearchBot
User-agent: Claude-User
User-agent: PerplexityBot
User-agent: Perplexity-User
User-agent: meta-externalagent
User-agent: meta-externalfetcher
User-agent: cohere-ai
# Примечание: Google-Extended и Applebot-Extended — это токены управления обучением моделей, а не HTTP-краулеры.
# Они не влияют на поисковую индексацию или цитирование в Google AI Overviews или Siri/Spotlight.
# Добавляйте "User-agent: Google-Extended" или "User-agent: Applebot-Extended" + "Disallow: /" только для отказа от обучения AI-моделей.
Allow: /
Disallow: /api/
Disallow: /admin/
Disallow: /private/
Disallow: /checkout/
Disallow: /auth/

Sitemap: https://[YOUR_DOMAIN]/sitemap.xml
```

## 📊 Научный базис и иерархия факторов цитирования

Эмпирический рейтинг техник по приросту цитируемости в генеративных движках ([исследование Princeton / Georgia Tech KDD 2024, arXiv:2311.09735](https://arxiv.org/abs/2311.09735)):

```
┌──────────────────────────────────────────────────────────────┐
│  ТЕХНИКА ОПТИМИЗАЦИИ                ПРИРОСТ ЦИТИРОВАНИЯ      │
├──────────────────────────────────────────────────────────────┤
│  1. Прямые цитаты экспертов (≥2)    +41%  ██████████████████ │
│  2. Точные цифры с единицами измер. +30%  █████████████      │
│  3. Ссылки на первоисточники / RFC  +28%  ████████████       │
│  4. Высокая беглость (Fluency)      +28%  ████████████       │
│  5. Точная терминология (Entities)  +18%  ████████           │
│  6. Легкая для понимания структура  +14%  ██████             │
│  7. Авторитетный, прямой тон        +10%  ████               │
│  8. Уникальный словарь (нейминг)     +6%  ██                 │
│  9. Переспам ключевыми словами      -8%   ▼ ШТРАФУЕТСЯ       │
└──────────────────────────────────────────────────────────────┘
```

> **Примечание к бенчмарку `[RESEARCH]`:** Эти проценты получены экспериментальным путем на выборке из 200 синтетических запросов в контролируемом бенчмарке (Aggarwal et al., 2024, Table 1), а не как универсальная гарантия для продакшн-ранжирования.
>
> **Синергия комбинаций:** В разделе 5.3 статьи Принстона комбинация **Fluency Optimization + Statistics Addition** превзошла лучшую одиночную стратегию более чем на **>5.5%** на тестовом подмножестве из 200 запросов.

### 🔑 3 Главных принципа современного GEO (Исследования 2025–2026)

1. **Brand Footprint и попадание в пул кандидатов `[RESEARCH]`:** В исследовании 75,000 известных брендов ($DR > 40$, Ahrefs) упоминания на диалоговых платформах (**YouTube ~0.737 корреляция**, Reddit, Википедия) продемонстрировали высокую корреляцию с цитированием в LLM, укрепляя узнавание сущности на 2-м этапе генерации. Традиционные бэклинки остаются обязательным фундаментом для 1-го этапа извлечения кандидатов.
2. **Цитируемость пассажей и независимость кореференций `[HEURISTIC]`:** Практическая RAG-эвристика. Самодостаточные смысловые блоки (~100–200 слов) с явным указанием сущностей вместо двусмысленных местоимений устраняют контекстную неопределенность и максимизируют вероятность извлечения.
3. **Платформенная дивергенция и дифференцированная свежесть `[RESEARCH]` & `[HEURISTIC]`:** Лишь **~11% доменов** цитируются одновременно в ChatGPT Search и Google AI Overviews по идентичным запросам. Оптимизация требует калибровки под движки и учет волатильности темы (ценообразование/софт против вечнозеленых протоколов RFC).

## 🖥️ Консольный движок автономного аудита CLI (v2.0.0)

`ultimate-seo-geo` включает встроенный детерминированный движок аудита с **нулевыми внешними зависимостями** (работает на стандартной библиотеке Python 3.10+ быстрее 500 мс). Он проверяет цели и формирует криптографически верифицированный Evidence Ledger с хэшем SHA-256:

```bash
# Аудит живого сайта с симуляцией поисковых AI-ботов
python -m engine.inspector https://example.com

# Аудит локального HTML-файла или артефакта сборки
python -m engine.inspector path/to/page.html

# Экспорт машиночитаемого JSON для CI/CD quality gates
python -m engine.inspector https://example.com --format json --output audit-report.json

# Проверка со специфической конфигурацией robots.txt
python -m engine.inspector https://example.com --robots path/to/custom-robots.txt
```

### Возможности детерминированного движка:
- **Симулятор доступа AI-краулеров по RFC 9309:** Парсинг AST robots.txt и детерминированная симуляция прав доступа для `GPTBot`, `ClaudeBot`, `PerplexityBot`, `Google-Extended` по правилам наибольшего совпадения (longest-match) и приоритета Allow.
- **Анализатор графа и AST Schema.org:** Проверка синтаксиса JSON-LD, верификация перекрёстных связей в едином `@graph` через `@id`, обнаружение изолированных сущностей (orphans) и валидация цен Google Merchant.
- **Анализатор контента и готовности к GEO:** Детекция прямого ответа в первом блоке, выявление вводного "воды"-текста, анализ распределения длины пассажей и проверка независимости местоимений (coreference).
- **Протокол Evidence Ledger:** 4-уровневый конвейер (`RAW` -> `SIGNAL` -> `EVIDENCE` -> `FINDING`) с фиксацией SHA-256 хэша входящего контента.
- **Строгий инвариант "Unknown != Failure":** Неизмеренные сигналы (например, реальные полевые данные CrUX при отсутствии API-ключа) не снижают балл и изолируются от подтвержденных дефектов.
